# OWL

OWL — проект переносимых инструкций (Agent Skills), справочных материалов, Markdown-шаблонов и текстовой конфигурации для разработки с AI-агентами. Первая целевая среда — OpenCode; общие материалы не должны зависеть от неё или от конкретного проекта. В OWL нет собственных скриптов, CLI, сервера или исполнителя workflow.

MVP проверен в OpenCode 1.18.33 в границах [итоговой приёмки](docs/verification_026.md): установка в новый и существующий тестовые проекты, повторная установка, постановка и интеграция одной задачи, выбор правил двух проектов, продолжение в другом дереве и отрицательные пробы. OWL остаётся набором инструкций, а не программным механизмом контроля. Удалённая публикация тестового проекта, одновременная запись несколькими координаторами и другие AI-среды не проверялись.

## Установка в проект агентом

Выберите конкретный коммит OWL (полный идентификатор), получите его чистую копию отдельно от целевого проекта и передайте агенту абсолютные пути к обоим каталогам. Попросите его **прочитать прямо в исходной копии** `skills/owl-init/SKILL.md` и выполнить предварительный осмотр, установку и проверку по инструкции; установленный `owl-init` для начала не нужен. Для чтения внешнего каталога в неинтерактивном OpenCode может понадобиться адресное разрешение по правилам вашего проекта. При конфликте инструкция останавливается, а не перезаписывает файлы. Она размещает пакет в отслеживаемой `.agents/` целевого проекта, сохраняет местные материалы и фиксирует ревизию в `.agents/OWL_INSTALL.md`.

После установки **из целевого проекта**, в том числе из его отдельного worktree, используйте уже установленные пути: `.agents/skills/owl-init/SKILL.md`, `.agents/docs/index.md`, `.agents/workflows/develop.md` и `.agents/integrations/opencode/README.md`. Последний документ объясняет отдельное подключение профилей и команд OpenCode с сохранением проектных настроек, проверку доступных моделей и выбор основного профиля `owl-advanced`. Перед использованием проверьте маршрут собственных `AGENTS.md → rules/index.md → применимые правила`; ссылки установленного пакета остаются внутри `.agents/`. Файл `README.md` исходного репозитория в пакет не копируется.

При установке инструкция создаёт пустую локальную очередь `.owl/tasks/ROADMAP.md` **в основном дереве**, если её ещё нет и каталог задач не содержит неизвестных данных; существующую очередь сохраняет. Это общая очередь для последующего `/owl-brief`, которую ведёт один координатор. `.owl/tasks/` и `.owl/worktree/` игнорируются Git и должны сохраняться отдельно при переносе работы; `.owl/workflows/` может отслеживаться. Новые деревья задач создаются в `.owl/worktree/<ID>/`; прежние зарегистрированные деревья остаются по фактическим путям Git. Перед работой в отдельном worktree проверьте, что исходная ревизия содержит необходимые документы и правила.

## Начало работы в OpenCode

После подключения команд по `.agents/integrations/opencode/README.md` выберите `owl-advanced`: `/owl-brief <запрос>` согласует требования и подготовит задачи без реализации; координатор назначает исполнителя в общей очереди. `/owl <ID>` ведёт назначенную задачу, `/owl` в координирующей сессии выбирает одну готовую задачу, `/owl-fix <проблема>` начинает диагностику. Проверяйте приёмку и разрешения проекта перед интеграцией. Из worktree передайте агенту **абсолютный путь** к очереди основного дерева, поскольку в отдельном дереве её копии нет. Для анализа уже выполненных задач отдельно попросите агента прочитать `.agents/skills/owl-self-review/SKILL.md`.

Фактические пробы и ограничения для каждой возможности перечислены в [приёмке](docs/verification_026.md). В частности, проверка `/owl` с ID и `/owl-brief` не означает, что все варианты команд испытаны в интерфейсе.
