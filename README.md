# OWL

OWL — проект переносимых инструкций (Agent Skills), справочных материалов, Markdown-шаблонов и текстовой конфигурации для разработки с AI-агентами. Первая целевая среда — OpenCode; общие материалы не должны зависеть от неё или от конкретного проекта. В OWL нет собственных скриптов, CLI, сервера или исполнителя workflow.

Сейчас в репозитории подготовлены тексты скилов, три схемы сценариев, шаблоны, инструкция установки и [образец интеграции OpenCode](integrations/opencode/README.md) для версии 1.18.33. Это материалы для дальнейшей сборки и проверки MVP, а не подтверждение их работы в целевом проекте. Пользовательские входы (`/owl-brief`, `/owl`, `/owl-fix`) ещё отсутствуют; сквозная интеграция в целевом проекте не проверена.

## Установка в проект агентом

Выберите конкретный коммит OWL (полный идентификатор), получите его каталог отдельно от целевого проекта и передайте агенту абсолютные пути к обоим каталогам. Попросите его **прочитать прямо в исходной копии** `skills/owl-init/SKILL.md` и выполнить предварительный осмотр, установку и проверку по инструкции; установленный `owl-init` для начала не нужен. Инструкция размещает пакет в отслеживаемой `.agents/` целевого проекта, сохраняет его существующие материалы, фиксирует ревизию в `.agents/OWL_INSTALL.md` и при конфликте не перезаписывает файлы. До применения учитывайте правила и разрешения целевого проекта. После установки подключите профили OpenCode по [инструкции](integrations/opencode/README.md) с сохранением проектных настроек; наличие пакета не подтверждает загрузку скилов или доступность моделей.

Локальная очередь — `.owl/tasks/ROADMAP.md` основного дерева (`.owl/tasks/` и `.owl/worktree/` игнорируются Git и должны сохраняться отдельно при переносе работы; `.owl/workflows/` может отслеживаться). Новые деревья задач создаются в `.owl/worktree/<ID>/`; прежние зарегистрированные деревья остаются по фактическим путям Git. Перед работой в отдельном worktree проверьте, что исходная ревизия содержит необходимые документы и правила.
