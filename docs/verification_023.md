# Проба 023: установка и одна задача

**Статус: приёмка задачи 023 завершена после повторной пробы ниже; приёмка всего MVP не завершена.** Первоначальный протокол относится к OWL `4ad848653e14078d203905be4cbcc9c1b35d3a99` и OpenCode `1.18.33`, к вызовам 3 октября 2026 года. Целевая приёмка — [§ 13 спецификации](owl_spec.md#13-критерии-готовности-mvp), постановка — в локальном `.owl/tasks/task_023/task.md` основного дерева. Это наблюдения из временных Git-проектов, а не утверждение о готовности MVP. Для проб соблюдены `AGENTS.md` → `rules/index.md` → `rules/development.md` и `rules/verification.md` OWL; в целевом проекте читались его `AGENTS.md`, `rules/index.md`, `rules/base.md` и `docs/counter_spec.md`.

Профиль `owl-advanced` подтверждён через `opencode debug agent owl-advanced`; реальные вызовы профилей `owl-standard` и `owl-review` выполнены при задаче, отзыв ревью указывает Sol 6.
- Новый Git-проект `/tmp/opencode/owl-023-new`: только отслеживаемый `README.md` (`1f29809`). Существующий `/tmp/opencode/owl-023-existing`: `AGENTS.md`, `rules/index.md`, `rules/base.md`, `docs/`, `.gitignore`, `opencode.json`, приложение и тест; начальный коммит `e4a849f`, тест `python -m unittest discover -s tests` — 1, OK; программа выводила `1\n`.

Это доступ к исходным инструкциям тестового запуска, а не настройка целевых проектов или глобальное ослабление разрешений.

## Наблюдавшиеся шаги

1. В новом проекте `opencode run --pure --model openai/gpt-6-sol` прочитал `skills/owl-init/SKILL.md` исходной ревизии и выполнил установку. Добавлены `.agents/`, `AGENTS.md`, `rules/index.md`, `.gitignore`; сохранён `README.md` (совпадающий Git blob). Все 30 файлов пакета совпали побайтово с источником; 11 `SKILL.md` имели нужные поля; 61 рабочая относительная ссылка вне образцов разрешилась. OpenCode-команды и профили отдельно не подключались и не проверялись в новом проекте.
2. В существующем проекте такой же вызов сохранил прежнюю фразу `AGENTS.md`, правила, спецификацию и настройку `formatter: false`; добавил недостающие инструкции, две строки `.gitignore`, `.agents/` и запись ревизии. Профили из образца объединены с проектным `opencode.json`, команды скопированы в `.opencode/command/` без замены исходных полей; запуск отдельного процесса `opencode run --pure --agent owl-advanced --command owl-brief ...` подтвердил загрузку команды и скилов. Установка/подключение закоммичены в тестовом проекте как `539b814`, чтобы исходная ревизия отдельного worktree содержала правила и конфигурацию. Команды и конфигурация — отдельный от `owl-init` шаг.
3. Первый вызов `owl-brief` с явно согласованным требованием `count() == 2`, CLI `2\n`, тестом и запретом на реализацию **остановился**: `.owl/tasks/ROADMAP.md` после установки отсутствовал. Ни спецификация, ни код в этой пробе не изменены. Координатор вручную создал очередь только в тестовом проекте. Повторный `owl-brief` обновил `docs/counter_spec.md`, создал единственную задачу 001 в очереди и постановку; `counter.py` всё ещё печатал `1`, старый тест проходил (1, OK): реализации не было. Это воспроизводимый дефект первоначального пути; задача исправления — 027 в локальной очереди OWL.
4. Координатор назначил 001 OpenCode. `opencode run --pure --agent owl-advanced --command owl 001` создал `.owl/worktree/001` из `539b814`, изменил `counter.py` и тест, получил 2 успешных теста и проверку точного stdout `b'2\n'`, stderr `b''`, затем независимое ревью с Git blob ID обоих проверенных файлов. Без разрешения на commit/merge агент остановился на `ready_to_merge`. После явного локального разрешения в рабочей записи повторный `/owl 001` сверил файлы с ревью, повторил проверки, закоммитил `f714509`, сделал `git merge --ff-only owl/task-001` в `main` и там повторил 2 теста и проверку точного вывода. Итоговый `main` — `f714509`, чистый; запись 001 — `done`. У временного проекта нет remote; push не проверялся и не был разрешён.
5. Повторная установка той же ревизии в существующий проект через отдельный `opencode run --pure` не внесла изменений: `git status --porcelain` пуст, все 30 содержательных файлов совпали с источником, `AGENTS.md`, `rules/base.md`, `docs/counter_spec.md`, `opencode.json` совпали с HEAD. Команда `python -m unittest discover -s tests` — 2, OK; 61 действующая внутренняя ссылка разрешилась. Широкая первая проверка ссылок ошибочно сочла за сломанные ссылки-примеры внутри fenced code и шаблонов; повторная проверка исключила примеры и получила 0 сломанных ссылок.
6. Отрицательная проба: `/owl 002` с назначенной, но пустой постановкой отказался создавать дерево или объявлять задачу готовой. Отдельная проба 003: независимое ревью приняло diff SHA-256 `4dcfe205e5adc64889c4331259101468970cb2bd4eeb3024ede651e0a758577f`, затем координатор изменил `counter.py` с согласованных 3 на 4. Повторный `/owl 003` обнаружил иной diff `e5423ce2d22d1d6afcc15484c7635d5f4aedd38247e258d3265ae04ad86e513d`, признал старое ревью устаревшим, восстановил значение, повторил 2 теста и точный CLI и запросил новое независимое ревью. Без разрешения на интеграцию 003 остался `ready_to_merge`; `main` не менялся. Отдельный отрицательный результат обязательного теста перед переходом в интеграцию пока не поставлен и не пройден.

## Вывод и продолжение

Сквозной путь удалось проверить **только после ручной подготовки очереди**. Для завершения приёмки сначала исправить дефект 027, затем повторить установку → brief → одну задачу на чистом проекте **без** ручной очереди и проверить остановку именно на отрицательной обязательной проверке. Отдельно повторить сверку профилей и обнаружения скилов в основном и отдельном дереве через `opencode debug`, не подменяя эти проверки наличием файлов. Пока эти шаги не пройдены, задачу 023 и MVP нельзя объявлять завершёнными.

Итог: препятствие 027 снято, непрерывный путь от установки до интегрированного и повторно проверенного изменения подтверждён для существующего проекта; новый проект был проверен первоначальной пробой, а поведение создания очереди в новом проекте дополнительно проверялось при исправлении 027. Полный вывод `opencode debug skill` в этой среде обрывается на 64–72 КиБ, поэтому им не подтверждено **полное** перечисление всех скилов; фактическая загрузка нужных скилов установлена вызовами команд в основном и отдельном деревьях. Удалённая публикация тестового проекта не испытывалась; переносимость и параллельность остаются предметом задач 024–026.
